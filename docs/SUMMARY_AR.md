## نظرة عامة

نظام إلكتروني متكامل يُدير دورة حياة مقابلات القبول من أول تسجيل المتقدم حتى اعتماد النتيجة النهائية. يعمل على المتصفح بالكامل (React + TypeScript)، وينشر على GitHub Pages للواجهة وعلى Sites لتخزين البيانات عبر API حقيقي مع قاعدة بيانات D1.

## الواجهات المبنية

### 1. بوابة المتقدمين (`applicant`)
- البحث بالاسم أو رقم الهوية.
- إذا كان المتقدم في بيانات القبول المستوردة تظهر بياناته لاستكمال الناقص.
- إذا لم يكن موجوداً يملأ نموذجاً جديداً.
- دعم الأرقام العربية والفارسية والإنجليزية في كل الحقول.
- بعد الإصدار تظهر بطاقة انتظار تحتوي الاسم ورقم الانتظار ومصدر التسجيل فقط — دون بيانات اللجان أو الدرجات.

### 2. شؤون المتدربين (`trainees`)
- مراجعة طلبات التسجيل والوثائق.
- إصدار أرقام الانتظار للمتقدمين.
- متابعة حالة كل متقدم عبر سلسلة الحالات.

### 3. إدارة الكلية (`college`)
- نظرة تنفيذية شاملة على سير المقابلات.
- نسب الإنجاز والنتائج المعتمدة.
- تقارير قابلة للتصدير بصيغة PDF وExcel/CSV.

### 4. رئيس القسم (`head`)
- توزيع المتقدمين على اللجان الثلاث.
- اعتماد النتائج النهائية.

### 5. لجان المقابلات (`committee`)
- اختيار رقم اللجنة أولاً، ثم اختيار مدرب واحد أو أكثر من قائمة كاملة مع رقم الحاسب.
- اختيار مترجم اختياري من قائمة ثابتة.
- نموذج تقييم مقابلة من 50 درجة يشمل:
  - لغة الإشارة (25 درجة)
  - المظهر العام (5 درجات)
  - المعلومات العامة من أسئلة رياضيات وإنجليزي (15 درجة)
  - سرعة الاستجابة للتعليمات (5 درجات)
- بنود نعم/لا: صعوبة مصاحبة، ضعف سمع، إتقان لغة الإشارة، ضعف قدرات، تميز.
- قائمة المتقدمين تعرض جميع المتقدمين وليس المسجلين في اللجنة فقط.

### 6. الاستعلام (`inquiry`)
- بحث مستقل عن أي متقدم بالاسم أو الهوية أو رقم الانتظار.

### 7. تقرير المصدر (`sourceReport`)
- إحصاءات تفصيلية لمصادر التسجيل (بوابة قبولي / مباشر).
- نسب الحضور لكل مصدر.

### 8. تقرير منصة قبولي (`qobooliReport`)
- مطابقة سجلات منصة قبولي مع النظام.
- عرض حالة المطابقة: مطابق بالهوية والاسم / مطابق بالهوية مع اختلاف الاسم / غير موجود.
- حالة الحضور لكل متقدم من المنصة.

### 9. تقرير الغائبين (`absent`)
- قائمة المسجلين من بوابة قبولي الذين لم يحضروا المقابلة.

### 10. داشبورد متقدم (`dashboard`)
- لوحة مؤسسية قابلة للتخصيص (السحب وإعادة الترتيب).
- مؤشرات تنفيذية (KPIs).
- رسوم تحليلية: مخطط خطي للحالات، مخطط دائري للنتائج، خريطة حرارة اللجان، أعمدة المقارنة، متوسط الدرجات.
- تنبيهات: غائبون، بانتظار المراجعة، غير موزعين على لجان.
- جدول ذكي مع بحث وفلترة وفرز.
- اختصارات سريعة لشؤون المتدربين، اللجان، تقرير قبولي، ومزامنة البيانات.

## نظام الحالات

```
غير محدد ← مستورد من بوابة قبول ← تسجيل جديد غير مكتمل
  ← بانتظار رفع الوثائق ← بانتظار استكمال بيانات المتقدم
  ← بانتظار مراجعة شؤون المتدربين ← يحتاج إلى استكمال أو تصحيح
  ← مكتمل ومعتمد ← تم إصدار رقم الانتظار
  ← بانتظار المقابلة ← المقابلة جارية ← تم التقييم
  ← بانتظار اعتماد رئيس القسم ← النتيجة معتمدة
  / معتذر أو لم يحضر / مستبعد
```

## نماذج البيانات الرئيسية

- **Applicant**: 25+ حقل يغطي الهوية، الوثائق، الدرجات، سجل التدقيق، اللجنة، النتيجة.
- **InterviewScores**: درجات المقابلة كاملة مع أسئلة 5 أجوبة وبنود نعم/لا.
- **Committee**: ثلاث لجان ثابتة.
- **StaffMember**: 10 أعضاء هيئة مع رقم الحاسب والمهمة.
- **AcceptedApplicant**: بيانات القبول المستوردة من بوابة قبولي.

## البنية التقنية

```
src/
  App.tsx          ← النظام الكامل (منطق + واجهات)
  App.css          ← نظام الألوان والتصميم المتجاوب والطباعة
  App.test.tsx     ← 18 اختبار (واجهات، تسجيل، لجان، تصدير، رسوم)
  data/
    acceptedApplicants.json   ← بيانات القبول المستوردة

scripts/
  import-accepted-applicants.mjs   ← تحويل Excel → JSON
  build-sites-worker.mjs            ← بناء Worker للنشر

db/
  schema.ts                  ← تعريف جداول D1
drizzle/
  0001_applicants.sql        ← SQL إنشاء الجداول
```

## API المنشور

| النقطة | الوصف |
|---|---|
| `GET /api/applicants` | جلب كل المتقدمين |
| `PATCH /api/applicants/:id` | تحديث متقدم مع سجل تدقيق |
| `POST /api/session` | تسجيل جلسة (الحد الأقصى 150 متزامن) |
